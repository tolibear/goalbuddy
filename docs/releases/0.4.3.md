# GoalBuddy 0.4.3: Durable Subagent Waits

GoalBuddy 0.4.3 replaces the premature one-timeout recovery rule with a durable, role-aware subagent wait contract.

## What changed

### A timeout is only an observation window

After each `wait_agent` timeout, the PM checks the actual agent status and delivered messages. A still-running agent continues through bounded observation windows rather than being replaced after one timeout.

### Read-only roles have the right liveness signal

Scout and Judge tasks are read-only, so file changes cannot demonstrate their progress. The PM does not interrupt Scout or Judge work before 20 minutes, or Worker work before 30 minutes, unless there is an explicit error, confirmed unavailability, scope violation, or help request.

### Fallback now needs proof

Interruption is allowed only for a terminal error, confirmed unavailability, scope violation, or multiple observation windows plus evidence of no execution. A timed-out observation window alone never justifies PM fallback. During long waits, the PM gives the owner short updates. External Claude Opus architecture reviews use waits of at least 1200 seconds.
