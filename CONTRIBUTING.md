# Contributing

Thanks for improving `goalbuddy`.

## Local Setup

Clone the repo and run the checks:

```bash
git clone https://github.com/Danielalnajjar/goalbuddy.git
cd goalbuddy
npm run check
```

## Skill Tree Sync

`codex-goal-compiler/` and `goalbuddy/` are the two canonical skill trees. Their directories under `plugins/goalbuddy/skills/` are generated mirrors—never edit them directly. After changing either canonical tree, run:

```bash
npm run sync:plugin
```

The test suite fails if any canonical/mirror pair differs.

## Local Install Test

GoalBuddy installs into Codex and Claude Code by default. Use temporary home directories so local testing does not overwrite your real install:

```bash
# Both targets
root=$(mktemp -d)
node internal/cli/goal-maker.mjs --codex-home "$root/codex" --claude-home "$root/claude"
node internal/cli/goal-maker.mjs contract --target codex --codex-home "$root/codex" --json
node internal/cli/goal-maker.mjs contract --target claude --claude-home "$root/claude" --json
node internal/cli/goal-maker.mjs doctor --target codex --codex-home "$root/codex"
node internal/cli/goal-maker.mjs doctor --target claude --claude-home "$root/claude"
rm -rf "$root"

# One target
tmp=$(mktemp -d)
node internal/cli/goal-maker.mjs install --target claude --claude-home "$tmp"
node internal/cli/goal-maker.mjs doctor --target claude --claude-home "$tmp"
rm -rf "$tmp"
```

## Package Check

Before opening a PR, verify the private local package contents:

```bash
npm pack --dry-run
```

The package should include both canonical skill trees, the CLI, docs, assets, and the Codex/Claude plugin surfaces. Compiler tests remain under `internal/test/` and must not ship inside either skill tree. The inherited `$goal-maker` compatibility skill is generated by the installer; do not add another tracked payload or extend it with new functionality.

## Releases

GoalBuddy is committed and pushed to the personal fork, then activated from the local checkout only after isolated contracts, doctors, package proof, and representative-board checks pass. It is never published over upstream npm. See [docs/releases](docs/releases/README.md).

## Contribution Guidelines

- Keep the runtime dependency-free unless there is a strong reason.
- Keep both canonical skills installable and their plugin mirrors byte-exact.
- Keep installation working for both Codex and Claude Code.
- Keep one routing front door: Codex Goal Compiler. Goal Prep is the explicit backend.
- Do not add new compatibility shims; version compiler contracts and fail closed.
- Prefer small, reviewable changes.
- Update README or templates when behavior changes.
- Run `npm run check` before submitting changes.
