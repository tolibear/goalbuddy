# AGENTS.md

GoalBuddy is Daniel Alnajjar's private, locally installed GoalBuddy distribution for Codex and Claude Code. It remains an MIT-derived fork of tolibear's original GoalBuddy, but this repository owns the installed product boundary and is not published over the upstream npm package.

## Repo Shape

- `codex-goal-compiler/` is the canonical user-facing routing and compilation skill.
- `goalbuddy/` is the canonical Goal Prep and execution skill payload used as the compiler's explicit backend.
- `goalbuddy/agents/` holds Codex TOML agent definitions (`goal_*.toml`).
- `plugins/goalbuddy/agents/` holds Claude Code markdown subagents (`goal-*.md`).
- `goalbuddy/scripts/` stays inside the skill because installed skill instructions call those scripts.
- `internal/` is package and development infrastructure, not skill content.
- `plugins/goalbuddy/` is the repo-local plugin scaffold. It contains:
  - `.codex-plugin/plugin.json` — Codex plugin manifest.
  - `.claude-plugin/plugin.json` — Claude Code plugin manifest.
  - `skills/codex-goal-compiler/` — byte-exact compiler mirror.
  - `skills/goal-prep/` — byte-exact Goal Prep/execution mirror.
  - `agents/` — Claude Code agent definitions (markdown).
  - `commands/` — Claude Code slash command definitions (markdown).
- `$goal-maker` and the legacy CLI name are inherited compatibility aliases generated by the installer. Do not add another compatibility surface or let these aliases influence new architecture; retire them in a separate explicit cutover.
- `goalbuddy/surfaces/local-goal-board/` is the built-in local board surface. There is no public extension catalog.

## Improvement Surfaces

When improving this repo, consider the compiler contract, `codex-goal-compiler/SKILL.md`, `goalbuddy/SKILL.md`, templates, checker behavior, CLI UX, plugin UX (both Codex and Claude Code), package contents, local board behavior, and docs. Do not assume a request only touches code.

## Package Rules

- Keep the runtime dependency-free unless there is a strong reason.
- Keep both canonical skill trees installable and byte-exact with their plugin mirrors.
- Keep one public routing surface: Codex Goal Compiler. Goal Prep remains an explicit/manual backend.
- GoalBuddy owns installation topology and runtime capabilities. The compiler consumes only the versioned `goalbuddy contract` projection and a required capability subset; never teach it GoalBuddy's file inventory, exact agent count, or internal doctor schema again.
- Keep installation working for both Codex (default) and Claude Code (`--target claude`).
- Do not add compatibility shims for future contract changes. Version the contract and fail closed.
- Keep package-only CLI and tests under `internal/`.
- Do not commit local `docs/goals/` run artifacts unless explicitly requested.
- Run `npm run check` before claiming implementation is complete.

## Release Rules

- This fork is a private local package. Never publish it as the upstream `goalbuddy` npm package.
- Build and validate candidate releases in an isolated branch/worktree and isolated Codex/Claude homes.
- Activation is a separate explicit step: update the local Bun filesystem dependency, refresh both harnesses from this checkout, run both contracts/doctors, and only then remove the old standalone compiler surface.
- Existing live boards are not migrated or rewritten as part of a runtime release.
